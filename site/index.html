Point it at your database. Get a working API.

Generaptr reads the tables of a MySQL or PostgreSQL database and writes an Express 5 + Drizzle API, with validation and an OpenAPI 3.1 document that describes it.

npx generaptr-cli

Node 22 or later. The CLI asks for the connection, then writes the project.

→

The generated API

api/
├── package.json        # exact versions of express, drizzle-orm, the driver, zod
├── drizzle.config.js
├── .env.example        # DATABASE_URL
├── openapi.json
└── src/
    ├── index.js
    ├── app.js          # one router per table
    ├── db/schema.js    # one Drizzle table per database table
    └── routes/users.js # list, get, create, update, delete
  • Each table with one primary key gets five routes. Link tables with a composite key get none.
  • zod schemas from drizzle-orm/zod check each request body. A bad body gets 400 with the list of problems.
  • Database errors get a generic 500. The response never shows the database message.
  • Defaults, enums, unique keys, and foreign keys come from the database, so a client can leave out the columns that the database fills.
cd api
cp .env.example .env    # set DATABASE_URL
npm start

Read from a database or a spec

A database

MySQL through information_schema, PostgreSQL through pg_catalog. The user needs read access only.

An OpenAPI 3.1 file

A file that generaptr wrote reads back to the same tables. Other files map by convention: each object schema becomes a table.

From either source, generaptr writes the full API, or only openapi.json. An OpenAPI file can target MySQL or PostgreSQL, so you can move a schema from one engine to the other.

Migrations

The generated API uses Drizzle Kit. Migrations go forward only: to undo a change, write a new migration.

npm run db:generate   # writes SQL from src/db/schema.js
npm run db:migrate    # applies the SQL
Warning: the first db:generate writes CREATE TABLE for every table. Do not run db:migrate against the database that generaptr read: those tables exist there already. Issue #168 tracks a baseline migration.

Generaptr stops with Unsupported type on any other type, and with Unsafe name on a table or column name that has characters other than letters, digits, and _.

Use it from code

The generaptr package holds the same steps as the CLI.

import { handlers, operations } from 'generaptr';

const db = new handlers.Postgres({
  host: '127.0.0.1', port: 5432, user: 'postgres',
  password: 'secret', database: 'shop', schema: 'public',
});
const schema = await db.readSchema();
await db.close();

await operations.api.generateApi('./shop-api', info, schema);
await operations.spec.generateSpec('./spec', info, schema);

info holds the name, version, description, author, and license of the generated project. The package README lists every export.

Known limits

  • PostgreSQL bytea and tsvector columns are not supported. #166
  • Routes read one table each; there are no relation includes yet. #167
  • The first migration has no baseline for an existing database. #168
  • OpenAPI input is JSON only. #169
  • The generated API pins the Drizzle 1.0 beta. #170
